### Bước 1: Khởi tạo Môi trường và Global Payment Authority Identity (GPIA) Root PKI

Định chế GPIA là Root CA tối cao mới, thay thế hoặc bao trùm lên các chứng chỉ cũ để đạt chuẩn thanh toán quốc tế (PCI DSS Level 1).

```bash
# 1. Khởi tạo thư mục làm việc và cơ sở dữ liệu CA
mkdir -p /mnt/q/Ubuntu-24.04/rootf/root/pki/{certs,crl,newcerts,private}
cd /mnt/q/Ubuntu-24.04/rootf/root/pki/
chmod 700 private
touch index.txt
echo 1000 > serial

# 2. Khởi tạo Khóa riêng 4096-bit cho GPIA Root CA
openssl genrsa -aes256 -out private/gpia-root-ca.key 4096

# 3. Phát hành Chứng chỉ GPIA Root CA tự ký (10 năm)
openssl req -x509 -new -nodes -key private/gpia-root-ca.key -sha384 -days 3650 \
  -out certs/gpia-root-ca.crt \
  -subj "/C=VN/ST=Hanoi/O=Axioledger Global/OU=Global Payment Authority/CN=GPIA Root PKI"

```

### Bước 2: Tạo Cross-Bridge CA (Cầu nối chứng chỉ 5 Pillars)

Cross-Bridge CA đóng vai trò là chứng chỉ trung gian liên hợp. Bất kỳ giao dịch nào từ $AXQ, $VPX,$SQX, $KPX hay$VRQ cũng sẽ được định tuyến và tin cậy thông qua chứng chỉ này.

```bash
# 1. Tạo Khóa riêng và CSR cho Cross-Bridge CA
openssl genrsa -out private/cross-bridge-ca.key 4096
openssl req -new -key private/cross-bridge-ca.key -out cross-bridge-ca.csr \
  -subj "/C=VN/O=Axioledger Ecosystem/OU=Inter-Pillar Routing/CN=Axioledger Cross-Bridge CA"

# 2. Tạo tệp cấu hình cấp quyền CA (bridge-ca.cnf)
cat > bridge-ca.cnf <<EOF
[ v3_intermediate_ca ]
subjectKeyIdentifier = hash
authorityKeyIdentifier = keyid:always,issuer
basicConstraints = critical, CA:true, pathlen:0
keyUsage = critical, digitalSignature, cRLSign, keyCertSign
EOF

# 3. Dùng GPIA Root CA để ký phát hành Cross-Bridge CA (5 năm)
openssl x509 -req -in cross-bridge-ca.csr \
  -CA certs/gpia-root-ca.crt -CAkey private/gpia-root-ca.key -CAcreateserial \
  -out certs/cross-bridge-ca.crt -days 1825 -sha384 -extfile bridge-ca.cnf -extensions v3_intermediate_ca

```

### Bước 3 & 4: Cấp Chứng chỉ Operator (Devnode) và Payment Gateway (mTLS)

Để triển khai mTLS (Xác thực TLS hai chiều), cả Client (Node) và Server (Payment Gateway) đều phải có chứng chỉ được ký bởi Cross-Bridge CA và sở hữu Extended Key Usage (`clientAuth`, `serverAuth`).

```bash
# Tạo tệp cấu hình cho Node và Gateway (mtls-endpoints.cnf)
cat > mtls-endpoints.cnf <<EOF
[ node_cert ]
basicConstraints = CA:FALSE
nsCertType = client, server
keyUsage = critical, digitalSignature, keyEncipherment
extendedKeyUsage = serverAuth, clientAuth
subjectAltName = DNS:axioledger-devnode.internal

[ gateway_cert ]
basicConstraints = CA:FALSE
nsCertType = client, server
keyUsage = critical, digitalSignature, keyEncipherment
extendedKeyUsage = serverAuth, clientAuth
subjectAltName = DNS:payment.axqprotocol.axq, IP:192.168.1.100
EOF

# ---------------------------------------------------------
# A. Cấp chứng chỉ cho Operator Node (axioledger-devnode)
# ---------------------------------------------------------
openssl genrsa -out private/axioledger-devnode.key 2048
openssl req -new -key private/axioledger-devnode.key -out axioledger-devnode.csr \
  -subj "/C=VN/O=Axioledger Ops/CN=axioledger-devnode"

openssl x509 -req -in axioledger-devnode.csr \
  -CA certs/cross-bridge-ca.crt -CAkey private/cross-bridge-ca.key -CAcreateserial \
  -out certs/axioledger-devnode.crt -days 365 -sha256 \
  -extfile mtls-endpoints.cnf -extensions node_cert

# ---------------------------------------------------------
# B. Cấp chứng chỉ cho Payment Gateway
# ---------------------------------------------------------
openssl genrsa -out private/payment-gateway.key 2048
openssl req -new -key private/payment-gateway.key -out payment-gateway.csr \
  -subj "/C=VN/O=Axioledger Finance/CN=payment.axqprotocol.axq"

openssl x509 -req -in payment-gateway.csr \
  -CA certs/cross-bridge-ca.crt -CAkey private/cross-bridge-ca.key -CAcreateserial \
  -out certs/payment-gateway.crt -days 365 -sha256 \
  -extfile mtls-endpoints.cnf -extensions gateway_cert

```

### Bước 5: Khởi tạo OCSP Responder Endpoint

OCSP (Online Certificate Status Protocol) cho phép kiểm tra trạng thái thu hồi chứng chỉ theo thời gian thực (Real-time Revocation Check) mà không cần tải toàn bộ danh sách CRL.

```bash
# 1. Tạo chứng chỉ chuyên dụng cho việc ký OCSP (OCSP Signer)
openssl genrsa -out private/ocsp-signer.key 2048
openssl req -new -key private/ocsp-signer.key -out ocsp-signer.csr \
  -subj "/C=VN/O=Axioledger Security/CN=AXIOLEDGER OCSP Responder"

cat > ocsp.cnf <<EOF
[ ocsp_ext ]
basicConstraints = CA:FALSE
keyUsage = critical, digitalSignature
extendedKeyUsage = critical, OCSPSigning
EOF

openssl x509 -req -in ocsp-signer.csr \
  -CA certs/gpia-root-ca.crt -CAkey private/gpia-root-ca.key -CAcreateserial \
  -out certs/ocsp-signer.crt -days 365 -sha256 -extfile ocsp.cnf -extensions ocsp_ext

# 2. Khởi chạy máy chủ OCSP Responder (Chạy ngầm ở Port 2560)
# Trong thực tế, bạn sẽ bọc lệnh này vào một Systemd Service
openssl ocsp -index index.txt -port 2560 -rsigner certs/ocsp-signer.crt \
  -rkey private/ocsp-signer.key -CA certs/gpia-root-ca.crt -text &

```
